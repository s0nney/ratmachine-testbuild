# Rate limiting

**There is none.** This document exists because that is easy to assume
otherwise — the application has a captcha, and a captcha looks like a throttle
without being one. Nothing in the application counts requests, counts failures,
or consults a clock before accepting work.

Audited 2026-09-22 against `1b432a6`.

## What gates a post

`PostController#create` runs four checks, in this order:

1. `check_captcha` — returns `true` immediately unless
   `RATMACHINE_CAPTCHA_ENABLED` is set. Off outside production.
2. `check_message_size` — the 1,024-character limit.
3. `check_filters` — the moderator word filters.
4. `Ban.exists?(ip_address:)` — a manual, moderator-applied block. A banned IP
   is redirected away rather than shown an error. See
   [`banning.md`](banning.md).

None of these is temporal. There is no `last_post_at` column, no per-IP
counter, no cooldown in `Usecase::CreatePost`, and no throttling plug in the
`:web` pipeline in `config/routes.cr`. A client that passes the four checks can
post as fast as it can open connections.

## What the captcha does and does not do

The captcha itself is documented end to end in [`captcha.md`](captcha.md);
what follows is only its effect as a throttle.

Each captcha is a database row (`captchas`: `id`, `value`, timestamps) plus a
PNG generated by shelling out to ImageMagick. The value is six lowercase
letters, `('a'.ord + Random.rand(26)).chr` — about 309 million combinations,
so blind guessing is not the threat. OCR is.

Two properties make it *slightly* throttle-like, both incidental:

**It is single-use, including on failure.** `Captcha.is_valid?` deletes the row
before comparing:

```crystal
found_captcha_value = found_captcha.value
found_captcha.delete() if destroy
found_captcha_value == value
```

The delete happens first, so a wrong answer burns the captcha just as a right
one does. One image cannot be attacked repeatedly. This is the only thing
making repeated attempts cost anything, and it is a consequence of statement
ordering rather than a designed lockout.

**It expires.** `destroy_old` removes rows older than five minutes, and runs on
every generate and every validation.

What it does not do:

- **It is not bound to anything.** A captcha id is not tied to a session, an IP,
  a form, or an endpoint. `ModController` validates against the same table, so
  a captcha minted on the board form is accepted at the mod login.
- **The pool is unbounded.** `CaptchaHelper.captcha_form` calls
  `Captcha.generate()` on every form render, which is every board page view. A
  script can bank a hundred captchas from a hundred page loads and spend them
  whenever it likes inside the five-minute window.

So the ceiling on posting is "how fast can you solve images", never "how many
posts per minute".

## What happens on a failed captcha

`check_captcha` sets `@status_msg` to `"Incorrect or expired CAPTCHA"` and the
action renders `create.ecr`, which is two lines: the message, and
`render_redirect()` — a `<meta http-equiv="REFRESH" content="1;url=...">` back
to the board, carrying the typed message and the sage flag in the query string
so nothing is lost.

That one-second refresh is the only delay in the system, and it is client-side
courtesy. A script ignores the meta tag entirely. Nothing is recorded: no
counter is incremented, no attempt is logged, no penalty accrues. **There is no
exponential backoff, no lockout, and no widening delay anywhere in the
application.** The cost of a wrong answer is one extra HTTP round-trip.

## The mod login is the sharper problem

`ModController#authenticate` has the same absence of counting, guarding
something far more valuable — a successful call sets a `session` cookie holding
an admin JWT.

```crystal
if user.nil? || !captcha_valid?
  redirect_to("/mod/login?failed=true")
```

Two defects, beyond the missing rate limit:

**The `||` short-circuits past the captcha.** When the password is wrong,
`user.nil?` is already `true`, so `captcha_valid?` never runs and the captcha
row is never consumed. A password-guessing loop can fetch a single captcha,
never spend it, and hammer passwords indefinitely. The captcha protects nothing
on this endpoint as written.

**Failures are anonymous and free.** No counter, no lockout, no delay, and the
redirect to `?failed=true` does not distinguish a bad password from a bad
captcha — which is good for enumeration resistance and useless for throttling.

## The cheapest attack is not posting at all

`Captcha.generate` runs `Process.run("sh", ["-c", "convert ..."])` and writes a
PNG into `public/dist/images/captcha/`. That happens on every form render,
which happens on every unauthenticated `GET /b/:board`, with no rate limit.

Requesting board pages in a loop spawns one ImageMagick process and one file
write per request, without ever submitting anything. That is the largest
unauthenticated resource cost in the application, and it is reachable by anyone
with `curl`. Files are cleaned up by `destroy_old` on the five-minute sweep, so
this is a CPU and process-table problem rather than a disk-filling one — but
the sweep only runs when somebody generates or validates a captcha.

## If this is to be fixed

Recorded as direction, not as a decision that has been made.

The natural seam for posting is `PostController#create`, immediately after the
IP is resolved from `X-Forwarded-For` and before `Injector.create_post` is
called — the same place, and the same IP, that the poster ID
(`PosterIdHelper`) already derives a per-IP-per-board-per-day identifier from.
A "last post at" keyed the same way is a small addition.

For the mod login, two separate changes: evaluate the captcha before the
password so a failure always consumes it, and add a per-IP failure counter with
a delay that grows. Those are independent; the `||` ordering is worth fixing on
its own merits whether or not a rate limit ever lands.

Whatever shape it takes, it needs a store. The application is single-process
and holds no in-memory state today, so an in-memory map is the cheap option and
a `posts`-adjacent column or a small table is the durable one. That choice has
not been made.
